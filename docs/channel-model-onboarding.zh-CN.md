# 52token 渠道与模型入库规范

适用范围：52token 开发环境。确认日期：2026-10-16。

本文记录已确认的维护规则；分组名称、分组建立及既有分组的调整由管理员处理。保存本文不代表已经批量迁移既有分组，也不代表新增了数据库唯一约束。

## 1. 分组与渠道

- 一个对外分组只绑定一个真实渠道，禁止同组混入第二个渠道。渠道按上游账户分别建立，不把不同账户的余额、凭据或成本合并。
- 分组展示名由管理员自行命名，不用展示名推断厂商或实际供应商。内部分组标识应保持稳定；改标识时须同步检查渠道、令牌及业务后端的绑定。
- 厂商是模型资料属性，例如 DeepSeek、xAI、千问；厂商筛选与分组路由分开维护。
- 同一型号可在不同渠道、不同分组重复出现。选择某个分组必须路由到该组唯一渠道；明确选择线路的令牌不使用跨分组自动回退。

## 2. 模型与价格的独立标识

- 模型入库和价格快照按 `channel_id + 精确上游模型 ID` 区分。前端列表也必须使用稳定的渠道、模型组合标识，不能只用展示名称作为列表键。
- 保留上游模型名的版本、日期、大小写及变体后缀。`gemini-3.1-pro-preview` 不等同于 `gemini-3.1-pro`，`deepseek-v4-flash-0731` 不等同于 `deepseek-v4-flash`。
- 模型资料可以通过已确认的别名归一厂商和介绍；这种资料归一不能用于模糊覆盖价格。
- 同步只能更新该来源绑定渠道下的准确模型，不得写入其它渠道的同名模型价格。缺少匹配、价格字段或价格来源时，标记未就绪，不借用其它渠道价格。
- 价格来源可被多个已明确绑定的同站渠道复用，但每个渠道的账户、充值比例、分组以及价格快照独立维护。

## 3. 人民币成本与分组倍率

统一以人民币采购成本扣费，不加价。上游的额度符号 `$` 不自动视为真实美元；先确认其代表平台额度还是美元，再应用对应的采购换算。

定义：`R = 每充值 1 元人民币获得的上游额度数`。

| 情况 | 渠道价格的处理 | 本地分组的处理 |
| --- | --- | --- |
| 充值折扣 | 标价除以 `R`，得到人民币基准价；例如充值 0.2 元到账 1 额度，`R = 5` | 不把充值折扣再乘一次 |
| 上游实际倍率为 1 | 按该渠道准确标价及充值比例生成成本价 | 本地分组可为 1 |
| 上游实际倍率低于 1 | 沿用 POJIA 方式：渠道保留未乘该倍率的人民币基准价 | 建独立分组，使用已确认的小数倍率；倍率由管理员维护 |
| 上游倍率高于 1、倍率不明，或接口已包含倍率 | 先核对来源字段和实际账单，明确哪一层已计入倍率 | 不直接套用低于 1 的模板，也不重复乘倍率 |

低于 1 的 POJIA 模式：

```text
人民币基准价 = 上游未乘分组倍率的标价 / R
实际扣费 = 按实际用量计算的人民币基准费用 × 本地分组倍率
```

上游实际倍率与本地分组倍率必须分别记录。正确映射为相同倍率时，最终只乘一次；不能既在渠道价格里折算 0.08，又在本地分组再乘 0.08。当前管理员允许承担低于真实成本的差额，禁止扣费高于真实采购成本。

小数分组方案必须使用该渠道已启用的本地分组计费模式；当前 POJIA 已启用。普通成本渠道可能固定按本地 1 倍结算，不能只修改分组倍率就认为已切换模式，入库时须核对实际实现和扣费结果。

POJIA 当前示例：`R = 1`，上游实际倍率为 `0.08`，本地独立分组 `x0.08 POJIA` 为 `0.08`。Flash 空闲基准输入、输出、缓存分别为 `¥1 / ¥4 / ¥0.02` 每百万 token；实际成本分别为 `¥0.08 / ¥0.32 / ¥0.0016`。分组展示名可由管理员维护，价格折扣不能因此改变。

普通输入、缓存读取、适用的缓存写入和输出分别计费；包含缓存的输入总量不能再重复收一次普通输入费。按次模型保存人民币请求价格表达式，不把它混成 token 单价。峰谷、上下文阶梯等条件必须保留；尚未核实的费率不能擅自推断。

## 4. 入库顺序

1. 管理员建立并命名分组，确认该组只对应一个渠道；低于 1 的倍率沿用上面的 POJIA 模式。
2. 建立渠道，填写上游根地址、调用凭据、`R`、实际令牌分组与倍率；余额凭据按该渠道账户分别维护。
3. 绑定该站价格来源，配置准确接口、字段映射、计价单位及是否已含上游倍率。
4. 从该渠道同步模型清单和资料，保留准确 ID，再归一厂商和资料；已有资料只补缺，价格独立处理。
5. 只同步该渠道价格，检查同名模型在其它渠道的价格未变化。检查小数倍率没有重复折算，展示金额与最终扣费使用同一口径。
6. 验证实际使用的接口及流式、非流式格式；核对输入、输出、缓存或按次费用与上游实际账单，再启用。缺少有效 usage 时不能用未经核实的本地估算冒充真实采购成本。
7. 创建绑定该分组的调用 key，限制允许模型。业务后端保存对应 key；前端只提交所选线路的稳定标识和模型，后端使用对应分组 key 调用。

## 5. 启用与回归检查

- 分组只有一个渠道，令牌指向正确分组，前端展示名不会改变路由身份。
- 每个模型都能追溯到自己的渠道、准确上游 ID、价格来源、同步时间和计费单位。
- 同名模型的价格、充值比例、账户倍率和余额互不覆盖。
- 流式响应有完整内容并正常结束；扣费按上游实际结算口径核对，不能因为返回字段异常而多收估算费用。
- 当前钱包精度为每配额点 `¥0.000002`。人民币成本结算向下取整，差额由平台承担，不向上加收；若钱包单位设置改变，应重新验证。
- 本规范是维护要求。未实施自动约束、未核实的峰谷价格和未完成实账验收的模型，必须如实记录状态。
